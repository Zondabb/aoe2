# AI 城墙防御、攻城与经济压制

外部 Python v3 多 Agent 负责战略与持续任务，Godot 执行真实的建造、训练、寻路和伤害；本地规则 AI 也按攻城与士兵两种职责选敌。单人外部 AI、单人托管和联机托管使用相同的 v3 执行器。

## 城镇中心防御

城墙防守角色默认使用 `balanced`：村民数量、粮食供应和军事生产建立后，分批围住基地，无需等到第一次遇袭。过去只建三侧短墙、默认最多 12 段，不能形成包围；现在默认总预算为 384 个墙体或城门实体，计入地基，模型可在 4–512 范围内调整。达到预算上限仅表示暂缓购买，不代表围合成功。

游戏围绕己方 TC 与附近核心建筑规划四面相接的周界，默认向各方向延伸 28 世界单位，按既有建筑和出兵口扩展，最远 44。第一笔墙体付款前，预览随基地发展扩大，并根据已见树林、矿点、水域有界调整边线，保留核心建筑与出口；开始施工后固定边界，后续建筑不会把已有围墙推向外侧。建筑候选为未来墙线预留空带，TC 周边继续保留农田、资源交付与横纵通道。四个方向各保留一座自动城门；时代未解锁城门时留下出入口，解锁后补齐。

墙线必须来自游戏提供的 `defense_options`，每批最多覆盖 8 格，优先修复被毁缺口、延续已有墙段并接上转角，完成后持续维护。`defense_plan` 提供总数、完工、待建、地基、不可见和受阻统计，只有全部墙体与城门真实完工才会报告 `closed=true`。周界默认使用经济实用的木墙，已固定周界的材料优先于模型后续偏好；接上的己方旧石墙可以复用，不会重复收费或免费升级。

边界未完全可见时，`defense_scout_options` 提供短距离探边点，防守角色最多借用一名空手村民逐步揭开迷雾，再按真实可见足迹建造。遇到可见敌军撤回；停滞或超时则取消探边、冷却后再试。不会夺取正在交付、施工或处于玩家手动保护期的村民。自然障碍或地形冲突会如实计入受阻段，不能把受阻缺口当作已封闭。

墙体采购在经济、建造、出兵与科技预算之后，保留木材和粮食；资源不足时向经济角色提出采集需求。建造位置检查整条线和工人与全部可见敌兵的距离，施工中断后继续已付款地基，避免重复购买。本地规则 AI 也使用相同周界、探边与续建规则。

浆果耗尽后的磨坊选址同时提供内圈和外圈备选，避免墙带和已有建筑挡住全部候选，导致农田供粮与续建一起停滞。单机存档保存周界边界、材料、固定状态和已完工历史，读档时重新绑定 TC 实体，继续原线施工；旧存档仍可加载。

大军寻路或换目标时，侦察和战斗移动指令最多占用每轮前 24 个额度，为后续科技、建设、训练、城墙和采集保留 12 个；总上限仍为 36。军队先处理回防单位，再按上次实际派发时间轮转，防止同一批士兵反复用满额度，使后续部队、造田和补墙长期停工。

基地受到攻击时，作战角色优先派普通兵拦截，优先处理正在攻击己方城镇中心的目标。防守人数依据可见威胁和可用兵力决定；足够的守军可以处理少量袭击时，正在攻城的部队继续进攻。

## 攻城生产链

城堡时代观察到敌建筑后，AI 主动提出攻城需求；遇到挡路城墙或拆城进度停滞也会提出需求。建设角色补齐攻城工坊所需的铁匠铺等前置建筑，再建工坊，生产角色从当前文明、时代和科技实际解锁的单位中选择。

攻城队伍有数量上限，并把已有单位、训练队列和未确认训练命令一并计数，防止重复下单。破城武器优先选择冲车；普通部队增长后可补充更多攻城单位，最多 4 台。资源不足时为攻城生产保留木材、黄金，继续安排粮食采集和经济生产；基地紧急防御时允许先补护卫。尚未形成攻城能力时，避免把全部黄金存入帝王时代升级。

建造储蓄区分“时代或前置未解锁”和“资源不足”。游戏目录中的 `available=false` 可能只是买不起，不能据此取消存钱；已经解锁的关键基础设施会继续积累资源，实际下单仍按当前预算与游戏校验执行。

基地拥挤时，建造候选扩展到 50、56、68 世界单位的外围，并加密外围采样方向，避免遗漏已经处于己方视野内的空地。仍检查完整建筑足迹可见、运输通道、出兵口和施工路径；每种建筑最多检查 4 条路径，输出 3 个合法位置。

## 战斗分工

| 部队 | 目标顺序与任务 |
| --- | --- |
| 冲车、投石车及其他拆建筑攻城单位 | 清除进攻路径上的可见城墙、关闭的城门，再集中攻击敌城镇中心；有射程直接命中建筑时无需先拆墙 |
| 普通步兵、骑兵、弓兵 | 先打附近守军及威胁攻城武器的敌兵，再攻击可见村民，压制采集；没有合适的敌方单位时协助拆建筑 |
| 弩炮 | 保持对单位的战斗用途，不作为冲车类拆建筑力量 |
| 侦察部队 | 搜索敌基地和通路，失去视野后复查记忆位置 |

攻击目标仍然合适时保持原命令，减少重复换目标；目标已摧毁或不可见时依据新观察调整。敌建筑记忆只提供搜索位置，不能用隐藏目标 ID 隔空下达攻击。

外部 v3 执行器为一次进攻保留共同突破口：部队集中拆一处墙，再清理附近墙段以形成可通行的宽度；确认开口后，后续援军先对齐缺口入口、穿过缺口，再继续攻击。这样避免每名士兵各拆一块墙，导致冲车穿墙后孤立无援。作为突破目标的城门打开后，部队释放拆门目标并通行；重新关门时恢复阻路判断。

投石车等有友军伤害的武器根据游戏提供的实际爆炸半径检查落点附近的己方单位与建筑。出现误伤风险时暂停尚未发出的攻击，友军离开后恢复；已经在空中飞行的石弹仍按游戏规则结算。

## 游戏机制修复

近战单位攻击建筑时，寻路终点放在建筑朝向己方的外缘，避免终点落入实体内部。城门旋转后，攻击距离、投射物瞄准和命中判定使用旋转后的占地。

冲车沿用已有原版建筑攻击加成，没有额外增加伤害。更快拆除来自正确生产攻城武器、保持建筑目标和打通进攻路线。自动战斗保持玩家已经下达的有效攻击和移动命令；AI 托管仍遵守现有手动控制保护。

## 使用和验证

重启 Python AI 服务，然后从 Godot 编辑器开始新对局，保持 `multi_agent_enabled=true`。现有服务地址与模型配置不需要新增选项。关闭多 Agent 后的旧版同步 LLM 执行器保留原行为。

针对性验证入口：

```powershell
# Python 决策、计数、预算、迷雾和防守分工
cd ai_service_python
.\.venv\Scripts\python.exe -m pytest tests/test_siege_strategy.py tests/test_wall_defense.py -q -p no:cacheprovider
cd ..

# Godot 实际寻路、城门几何、冲车伤害和选敌
& '<Godot控制台程序路径>' --headless --path . --script res://tests/run_siege_ai_mechanics.gd

# 完整周界几何、四侧碰撞、城门通行、迷雾和缺口修复
& '<Godot控制台程序路径>' --headless --path . --script res://tests/run_defense_perimeter.gd

# Python HTTP 决策 + Godot 自然采集、探边、分批施工及破口重建
.\ai_service_python\.venv\Scripts\python.exe tools/test_ai_perimeter_e2e.py --godot '<Godot控制台程序路径>'

# 本机 Python HTTP 服务 + Godot 完整攻城对局
.\ai_service_python\.venv\Scripts\python.exe tools/test_multi_agent_e2e.py --godot '<Godot控制台程序路径>' --siege-scenario --duration 650 --timeout 240 --planner-delay 0.3 --require-victory --require-walls

# 普通黑暗时代开局：发展到实际建墙、建工坊、训练冲车并获胜
.\ai_service_python\.venv\Scripts\python.exe tools/test_multi_agent_e2e.py --godot '<Godot控制台程序路径>' --duration 2400 --timeout 720 --planner-delay 0.3 --require-victory --require-walls --require-siege
```

攻城场景从城堡时代与有限资源开始，有敌方墙线、守军和村民。AI 必须自行建造攻城工坊、训练冲车、破墙并最终摧毁敌城镇中心。测试使用本机模拟模型返回高层计划，不消耗外部模型额度，也不向执行器注入单位命令。标准开局测试使用同一工具但不传 `--siege-scenario`，覆盖从黑暗时代发展经济、侦察和进攻的流程。
