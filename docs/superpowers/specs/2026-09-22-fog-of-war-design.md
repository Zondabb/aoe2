# 战争迷雾与阵营视野调试设计

日期：2026-09-22

状态：设计方案，尚未实现。本文中的新增类型、接口和默认参数均为待实施约定。

适用：当前 Godot 4.7.1、Compatibility 渲染器、等距 2D 地图；与已实现的玩家色索引蒙版 Shader 共存。

## 1. 功能结果

地图对每个阵营分别记录“从未探索”“已探索但当前不可见”“当前可见”三种状态。未探索区域完全黑色；单位离开后，地形保留并变暗，敌军消失；见过的敌方建筑保留最后一次看到的外观。再次进入视野时，更新为真实状态。

按 **G** 进入调试模式，在面板中单选“玩家阵营视野”“AI 阵营视野”或“全图可见”。再次按 G 退出，恢复场景的正常视角。查看其他阵营或全图时，不改变任何阵营的探索记录、AI 输入或单位控制权。

《帝国时代 II》官方教学说明了开局黑色未探索地图，以及视线外敌军和未发现建筑会被隐藏的基本规则；本方案沿用这一体验。网格精度、建筑视野、追击行为等细节以下文项目约定为准，不声称逐项复刻原作所有版本。[官方探索教学](https://www.ageofempires.com/learn-to-play/expanding-your-empire-aoe2/)

## 2. 仓库现状及必须解决的问题

| 已有位置 | 当前实现 | 本次设计的接入方向 |
|---|---|---|
| `scripts/systems/vision_service.gd` | 空间哈希及圆形半径查询 | 保留邻域查询，新增阵营共享的地图可见性服务 |
| `vision_service_holder.gd` | 注册、移动同步、场景重建 | 与新迷雾服务协调生命周期 |
| `UnitDef.vision_radius`、单位 override | 已支持单位视野半径 | 复用当前配置；不重新定义所有兵种数值 |
| `BuildingDef` | 没有显式视野字段 | 补齐建筑及施工中视野参数 |
| `scripts/presentation/nav_debug_overlay.gd` | G 切换全部调试图层，V 绘制视野圈 | G 改为统一调试模式入口；视野圈是可选图层 |
| `scripts/match/pathfinding_test_controller.gd` | 也处理 G | 移除重复处理，避免一次按键触发两种行为 |
| `SelectionController2D` | 拾取敌人时没有统一视野判断 | 点击、框选、右键目标统一走可见性判定 |
| `ObservationBuilder` | 按观察者半径过滤部分敌人及资源 | 与画面使用同一阵营可见性语义 |
| `shaders/player_color.gdshader` | Billboard 已用玩家色 Shader | 不给 Billboard 覆盖另一个迷雾材质 |

当前代码还存在两个与迷雾直接相关的泄露入口：

1. `ObservationBuilder.build()` 在敌方建筑的可见性过滤之前填写 `derived.enemy_tc_id / enemy_tc_pos`，可能暴露未发现城镇中心。
2. `_is_entity_visible()`、`_resource_visible()` 在观察者为空时返回 true。所有己方视野源死亡后，不应因此获得全图情报。

`AutoCombatDirector` 的 `aggro_radius` 可以大于视野半径，并且会保留现有目标。只遮住画面不能阻止自动索敌或通过 `_attack_target` 追踪迷雾里的移动敌人，必须同步约束这些逻辑。

旧视野设计文档中的默认数值部分已经过时。实施以当前 `.tres`、`resolved_vision_radius()` 和代码为准：例如村民、弓箭手现为 16，诸葛弩为 10，其他单位可使用 UnitDef 默认值；不直接套用旧文档的统一 8。

## 3. 三态规则

每个阵营保存两张逻辑地图：

```text
visible_now[team][cell]   当前是否处于该阵营任一有效视野源范围内
explored[team][cell]      该阵营是否曾经看见这个格子

explored_next = explored_previous OR visible_now
```

| 状态 | 条件 | 地形 | 敌方移动单位 | 敌方建筑/可变化资源 |
|---|---|---|---|---|
| 未探索 UNEXPLORED | explored=0 | 纯黑 | 隐藏 | 隐藏；没有记忆则不显示 |
| 已探索 EXPLORED | explored=1、visible=0 | 约 40% 亮度 | 隐藏，不留下静止替身 | 显示最后可见快照，整体变暗 |
| 当前可见 VISIBLE | visible=1 | 正常 | 显示实时状态 | 显示实时状态并刷新记忆 |

约束：

- `visible_now` 可以增加或减少；本局 `explored` 只能增加。
- 双方数据隔离，同一阵营内所有有效视野源取并集。
- 没有视野源时 `visible_now` 全空，`explored` 保留；不是全图可见。
- 新对局或竞技场真正重开清空两张地图及记忆；只开关调试面板不清空。
- 黑色区域仍然可以下达地面移动命令以探索；不能凭实体 ID 选中或攻击其中的目标。
- 当前地图没有地形高度、城墙遮挡及驻军系统。本阶段采用无障碍圆形视野，不加入高地、树木阻挡、联盟共享、科技加成或作弊码系统。

## 4. 视野源与可见对象

### 4.1 有效视野源

| 对象 | 是否提供视野 | 半径 |
|---|---|---|
| 存活单位 | 是 | 现有 `resolved_vision_radius()`，包括实例 override |
| 已完成且存活的己方建筑 | 是 | 新增 `BuildingDef.vision_radius`，初始默认 16，延续当前服务的建筑回退值 |
| 已实际落地的施工建筑 | 是 | 新增 `construction_vision_radius`，初始建议 2 |
| 放置幽灵 | 否 | 预览不能探图 |
| 死亡单位、尸体、已摧毁建筑 | 否 | 移除源，但不抹除历史探索 |
| 箭矢、资源、记忆快照 | 否 | 不属于观察者 |

视野来源使用逻辑坐标 `sim_pos`。新增建筑参数是项目初始平衡选择，不是原作数值表。新服务应显式区分 UnitDef 与 BuildingDef，避免把 BuildingDef 强转为 UnitDef 后意外走默认分支。

### 4.2 判断实体是否被看到

- 单位、箭矢及小型资源：使用逻辑位置所在格子。
- 建筑：使用 `BuildingDef.footprint` 覆盖的逻辑格子，任一格可见则认为该建筑被发现，显示整个建筑。
- 不使用精灵图片尺寸推导建筑占地，也不使用为选择框扩大的 `IsoMath.footprint_polygon_screen()` 作为真实占地。
- 己方对象始终可在己方视角中查看；大多数对象自身也提供视野。死亡动画能否显示由当前位置可见性决定，死亡对象不再揭开地图。
- 发现建筑按完整实体处理；屋顶可以伸到地面视野边界外。这是本阶段明确的展示规则，避免按屋顶像素对应的地面格子把建筑切碎。

所有实体可见性判断使用同一套网格规则。圆形邻域查询继续作为候选筛选，不另造一套与画面冲突的探索历史。

## 5. 地图数据与更新

### 5.1 分辨率、边界与内存

新增 `FogOfWarService`，作为 RefCounted 逻辑服务，由场景级 `FogOfWarHolder` 持有。每局单独实例，禁止把探索历史放进静态全局变量。

初始参数：

| 参数 | 值 | 说明 |
|---|---|---|
| `cell_size` | 1.0 逻辑单位 | 与当前导航格同量级；数据结构独立 |
| 更新周期 | 0.1 秒，10 Hz | 原子发布一次双方可见性结果 |
| 地图边界 | bootstrap 传入 | 正式局约 -60～60，战斗竞技场约 -40～40，不在服务中写死 |
| 地形迷雾 alpha | 未探索 1.0；已探索 0.6；可见 0.0 | 可调视觉参数，不影响逻辑 |
| 数据存储 | 每队两个 PackedByteArray | 0/255，便于上传纹理 |

正式局 120 × 120 个格子时，双阵营的 visible/explored 基础数组共 `120 × 120 × 2 × 2 = 57,600` 字节，约 56.25 KiB，不含临时缓冲、对象记忆和 GPU 纹理。

`world_to_cell = floor((world - map_min) / cell_size)`。负坐标使用 floor。范围判定先拒绝地图之外的位置；恰好处于允许的 map_max 边界时，映射到最后一格，避免合法边界实体落入数组之外。格子中心和地图最大边缘不足整格的情况需统一处理。

### 5.2 首阶段算法

每次更新建立空的 `next_visible`，按当前有效源在其包围盒内扫描格子，比较格心到视野中心的平方距离，然后 OR 到所属队伍。最后与历史 explored 合并。

圆与格心采样会有最多约半个格子对角线的边界近似，这是本阶段逻辑精度。渲染柔化不能改变逻辑可见性；如果以后需要更细边界，可把 cell_size 调为 0.5，所有消费者继续读同一服务。

视野源注册事件包括初始生成、训练出兵、建筑落地、施工完成、死亡、销毁、位置及半径变化。移动过程中正常按 10 Hz 刷新；新增/移除视野源触发下一次物理提交的提前刷新，不等到满 0.1 秒。地图初始化必须在第一幅正式画面及第一轮 AI 观察之前同步完成一次。

同一更新事务完成以下步骤后才发布 revision：

1. 收集当前场景视野源，计算双方 next_visible。
2. 更新双方 explored。
3. 按新可见性刷新对象记忆，确认重新看见的空地。
4. 原子替换双方数组，增加 `revision`，通知画面及观察构建器。

不允许先更新玩家画面、后更新 AI 过滤而跨用两份半成品状态。更新频率带来的短暂可见性延迟以 100 ms 为目标上限；帧耗时过长需记录指标，不把这一目标当作已测保证。

先采用容易验证的全量重算。只有基准证明需要优化时，再引入脏格、视野覆盖计数或分块；覆盖计数实现必须正确处理重叠源撤离，不能清掉仍被其他单位看见的区域。

### 5.3 建议接口

```text
FogOfWarService.setup(map_rect, cell_size, teams)
FogOfWarService.rebuild(sources, renderable_entities)
FogOfWarService.update(delta)
FogOfWarService.state_at(team, sim_pos) -> FogState
FogOfWarService.is_entity_visible(team, entity) -> bool
FogOfWarService.is_footprint_visible(team, sim_pos, footprint) -> bool
FogOfWarService.get_known_static(team) -> 只读快照集合
FogOfWarService.reset_match()
FogOfWarService.changed(revision)
```

`VisionService` 保留空间查询和现有注册接口；`FogOfWarService` 维护地图状态及知识。Holder 从匹配的对局根节点获取服务，避免多个场景加载时误用 `get_first_node_in_group()` 找到其他对局的状态。

## 6. 建筑与资源的最后可见状态

已探索迷雾下直接绘制真实建筑再调暗，会泄露其升级、施工完成和被摧毁等变化，因此新增 `FogMemoryStore`。

每个阵营只在对象当前可见时写入快照：

```text
source_entity_id、kind、def_id、civ_id、team_color_id
last_seen_pos、logical_footprint、last_seen_time
sprite_base、frame_index、flip、scale、hotspot
当时已观察到的外观状态
```

快照是值数据和共享美术资源描述，不是对真实 Node 的持续引用。离开视野后：

- 敌方单位不建立地图静止替身；追击所用最后位置另行保存。
- 敌方建筑以及可能耗尽/消失的树木、矿石、浆果显示快照代理。
- 已探索但从未见过的新建筑，不会因为地形已知而自动出现。
- 真实建筑在迷雾中消失，旧快照继续保留；再次看见其全部旧占地并确认不存在时移除。不能因 `queue_free()`、EntityRegistry 注销或收到全局销毁事件直接删掉敌方快照。
- 再次看到同一建筑时替换旧快照；不同阵营可以保留同一对象的不同时刻外观。
- 资源剩余量、敌方 HP、训练队列、攻击目标不能从实时对象补进迷雾中的 UI。可展示“最后发现于 xx 秒前”，不展示实时数值。

`FogMemoryView` 只负责渲染，与实体处于一致的 Y 排序空间。可以作为 Entities 下的纯视觉节点，但不携带 UnitDef/BuildingDef 等模拟接口、不加入 units/buildings/resource_nodes 组、不注册 EntityRegistry、不参与寻路和碰撞。

真实实体在视野外继续生产、移动、受伤和采集，迷雾绝不冻结模拟。渲染可见性与游戏对象是否仍可绘制分别保存：例如耗尽资源自己的隐藏状态，不能被“切到全图可见”错误恢复。

## 7. 渲染方案

采用 **地形迷雾层 + 实体可见性管理 + 静态记忆代理**，保留已有阵营颜色 Shader。

### 7.1 地形迷雾层

在与地图相同的世界 Canvas 中新增 `FogOverlay2D`。推荐绘制顺序：

```text
地形与地表装饰              z = -100
FogOverlay2D               z = -50
真实实体/记忆代理/自身阴影   z = 0，沿用 Y 排序
普通世界标记               z = 50，服从视野规则
调试线框                    z = 80，仅调试模式
UILayer                    CanvasLayer = 10
```

相机缩放和平移自动作用于世界迷雾层。迷雾面片使用 `IsoMath.world_to_screen()` 投影逻辑矩形顶点，UV 对应地图格子；不用原图集 UV，也不用重新解释屏幕坐标。Godot 的 CanvasLayer 与世界 Canvas 分离，因此 HUD 保持在独立 UI 层，不被地形迷雾压暗。[Canvas layers 官方文档](https://docs.godotengine.org/en/stable/tutorials/2d/canvas_layers.html)

选定阵营的纹理通道约定：R=当前可见，G=历史探索。Shader 输出黑色及下列 alpha：

```text
if explored == 0: alpha = 1.0
elif visible == 0: alpha = 0.6
else: alpha = 0.0
```

纹理为小尺寸数据纹理、最近邻、无 mipmap。首版使用明确格子边界；若增加柔化，只向已知区域内部过渡，未探索格子保持完全不透明，不能通过线性插值泄露黑色边缘的地形。

地图面片必须覆盖实际草地贴片外伸的边缘；逻辑地图之外采样一律返回黑色，底背景也为黑色。不同场景的地图尺寸、窗口尺寸及 0.45～1.8 相机缩放都要验收，不能只覆盖屏幕初始位置。

首次创建纹理，之后仅在迷雾 revision 变化时更新内容；保持纹理尺寸/格式一致，复用 `ImageTexture.update()`，不逐帧创建大纹理。[ImageTexture 官方文档](https://docs.godotengine.org/en/stable/classes/class_imagetexture.html)

### 7.2 实体显示

地形层不会自动隐藏其上方的单位，必须有 `FogPresentationController` 逐类执行：

| 对象 | 当前可见 | 不可见 |
|---|---|---|
| 实时单位、尸体、箭矢、战斗效果 | 按其原有规则绘制 | 整个视觉根节点隐藏，包括血条和阴影 |
| 实时敌方建筑/资源 | 正常绘制并更新快照 | 隐藏真实节点，只绘制已知快照 |
| 静态地面/不可变化装饰 | 地形层正常显露 | 由地形迷雾遮挡 |
| 建筑/资源记忆代理 | 隐藏，避免与真实图重叠 | 若已知则绘制，RGB 乘 0.4 |

实时单位按逻辑位置切换整体显示，避免身体、武器被屏幕上的地形遮罩截断。贴图内置阴影和额外 GroundShadow 必须同进同出。

迷雾控制实体根节点的显示资格；阵营色仍由 Billboard 原材质处理。快照代理使用独立父节点 modulation 变暗，使现有玩家色 Shader 继续生效，不能修改共享 ShaderMaterial 的 uniform 来做逐实例迷雾状态。

切换调试视角时在同一帧更新地形纹理、实体可见性及记忆代理，再展示新视角，避免出现“AI 的雾 + 玩家看见的单位”的混合画面。

## 8. G 调试模式交互

新增 `DebugViewController` 和 `FogDebugPanel`，将 G 从各个绘制器移交给统一控制器。

面板示意：

```text
调试模式                                      [G 退出]
观察视角
  (●) 玩家阵营 · 中国 · 蓝色
  ( ) AI 阵营 · 条顿 · 红色
  ( ) 全图可见

[ ] 显示本视角的视野范围圈
[ ] 显示迷雾网格
[ ] 显示寻路调试图层
图例：黑色=未探索  暗色=已探索  明亮=当前可见
已探索 xx%  当前可见 xx%  视野源 xx  最近更新 xx ms
调试观察期间只查看，不下达游戏指令
```

阵营名称从本局文明及 `TeamColorCatalog` 生成，不写死中国蓝色/条顿红色。阵营编号和玩家色编号是不同概念。

| 操作 | 行为 |
|---|---|
| 正常模式按 G | 保存基础视角及输入状态；打开面板，进入只读调试 |
| 选择玩家/AI 阵营 | 展示该阵营独立的 visible、explored 与记忆；不共享两方数据 |
| 选择全图可见 | 停用地形遮罩，显示所有当前真实对象，隐藏记忆替身 |
| 全图切回某阵营 | 恢复该阵营原有地图状态，未探索区域仍然黑色 |
| 再按 G | 关闭调试 UI 和调试线框，恢复场景基础视角及原输入权限 |
| 对局重开 | 清空调试临时状态，使用场景初始视角 |

G 开关不暂停模拟。调试期间禁用右键命令、建造落地、训练/指令按钮及其他会修改对局的快捷键，允许相机移动和只读查看当前视角可见对象。进入时取消尚未落地的建造幽灵；切视角清理拖选和当前选中对象，退出时只恢复仍合法可见的原己方选择。

输入通过 InputMap 的 `toggle_debug_mode` 绑定 G，忽略按键重复；文本输入框拥有焦点时不抢走正常文字输入。`NavDebugOverlay` 及旧 `pathfinding_test_controller` 不再独立消费 G。

保留原寻路网格、路径和视野圈复选框，但只有调试模式启用。视野圈默认只画所选阵营的视野源；全图模式才允许同时显示双方。原 A 热键与 WASD 相机移动冲突，移动箭头改为面板复选框，避免观察时意外切换图层。G 不再默认开启所有图层及高频计时日志。

场景基础视角：正式对战及战斗竞技场为 PLAYER；`ai_vs_ai.tscn` 保留观战用途，基础视角可配置为全图可见，且始终只读。即使观战画面为全图，两个 AI 仍各自受真实视野限制。寻路测试场景可保持全图基础视角，并通过 G 查看指定阵营迷雾。

## 9. 显示、操作与 AI 必须分离

```text
实际战斗归属：command_team / entity.team
真实知识状态：FogOfWarService[team]
当前显示方式：DebugViewState {debug_enabled, mode, viewed_team}
```

`mode=OMNISCIENT` 只作用于画面和调试只读查看。不能执行“把 explored 全部设为 1”，不能修改 VisionService 的半径，也不能传入 AI 观察构建器。

### 9.1 点击与建造

`_enemy_at_screen()`、资源拾取、框选、HUD 信息、悬停高亮都要先检查对应视角和操作阵营的可见性。不能只依赖 `CanvasItem.visible`，因为全图调试会改变显示状态。

正常模式下允许向黑色或已探索区域发出 MOVE。对未显示的目标不生成 ATTACK/GATHER 实体命令。记忆建筑不可作为实时攻击目标；右键其位置可以先转为地面移动，重新进入视野后再索敌。资源记忆同理，可前往最后位置，抵达后再验证采集对象，不能远程得知它是否耗尽。

首阶段建筑占地必须全部处于操作阵营当前视野，才做真实碰撞/资源检查和允许确认。这比原作部分操作更保守，但能明确避免幽灵颜色暴露隐藏障碍；未知区域只提示“需要视野”，不区分是否被敌人占据。官方曾修正建筑蓝图泄露未探索区域占用情况的问题，本项目也将这一入口列入验收。[AoE II DE 官方更新 44725](https://www.ageofempires.com/news/aoeiide-update-44725/)

### 9.2 索敌与追击

- AutoCombatDirector、AI 本地查询与命令校验都增加 `FogOfWarService.is_entity_visible(attacker.team, target)` 条件。`aggro_radius=40` 只扩大候选搜索，不自动揭示 40 范围内敌军。
- 已有 `_attack_target` 失去己方共享视野时，不再读取其新的 `sim_pos`、HP 或新路径。
- 保留最后一次可见位置，解除实时目标追踪，最多移动到该位置。途中重新看到敌人则恢复合法目标；到达仍不可见则停止该次追击并按原空闲索敌规则处理。
- 攻击动作到命中/发射事件时重新检查目标资格。已发射箭矢按释放时保存的轨迹/目标点继续模拟，不能为了画面视野而取消已有伤害；隐藏区域中的投射物和命中效果不显示，不反向揭示目标。
- 攻击范围、警戒范围、视野半径仍为三个不同概念；同阵营另一单位提供视野可以让目标具有被攻击资格，但不绕过距离与冷却规则。

### 9.3 观察、事件与协议

`ObservationBuilder` 的真实实体列表只包含己方信息及本方当前可见的敌人/资源。`enemy_tc_id/pos` 仅在当前可见时写入，否则保持现有未知哨兵值；历史位置通过独立知识记录表达，不能冒充实时目标。

静态历史信息建议增加可选字段 `known_static`，内容来自快照，带 `last_seen_time`；其中的 source ID 只用于对照，不能据此绕过实时 ATTACK/GATHER 校验。协议 schema、Python models、提示词与命令映射需一并更新。若首阶段 AI 不消费该字段，可以忽略；不能继续把它塞进当前可见 entities。

事件流同样按接收方知识过滤：己方经济/对象事件可接收；敌方建造、移动、死亡或资源耗尽只有实际观察到时才可报告。请求中的隐藏/不存在目标统一返回不可用，不通过不同错误消息泄露其生死或资源余量。

无己方观察者返回空敌情。正式带迷雾的场景如果服务尚未初始化，暂缓首个 AI tick，并保持黑色初始化遮罩；不能静默回退到全图查询。旧的无迷雾单元测试必须显式采用 `fog_enabled=false` 的测试配置，避免把兼容回退带入正式对局。

当前寻路/碰撞仍可使用真实地图保障模拟正确。本阶段不实现每阵营独立的未知障碍寻路知识图；正常玩家界面不能显示未观察到的敌方障碍轮廓，调试路径细节只在明确调试状态下查看。

## 10. 启动、重开和保存边界

启动顺序：创建 MatchState → 配置地图边界 → 创建 Vision/Fog 服务 → 生成实体并完成注册 → 首次计算双方迷雾及记忆 → 绑定显示与输入 → 启动 AI。旧 bootstrap 的 deferred 添加节点流程应集中到一个完成回调，避免首帧短暂全图可见。

竞技场重开先停输入与 AI tick，清理旧实体和快照，再清空双方 visible/explored、重建视野源并首次提交。事件回调需带本局世代或断开旧连接，防止旧对象的延迟注销污染新对局。

暂停/结束时冻结模拟视野更新；仍可通过 G 查看最后一次双方真实视野或全图。未来存档至少保存 explored 与静态记忆，visible 由存活视野源重建；本阶段不新增完整存档系统。

## 12. 测试与验收

### 自动化逻辑测试

1. 初始无源全黑；新增一个源只揭开所属阵营；另一阵营数据不变。
2. 单位离开后 visible 清除、explored 保留；重叠视野中的一个源撤离不影响另一个。
3. 死亡、建筑销毁、施工完成、出兵和半径变化正确更新；幽灵、箭矢、快照从不提供视野。
4. 两个阵营全部失去视野源，仍只保留各自历史地图，不返回全图敌情。
5. 验证负坐标、map_max、地图外、不同地图尺寸及建筑跨多格占地。
6. 敌方建筑被发现后在迷雾里销毁/新建/改变外观，不更新快照；重返视野才更新或清除。
7. 黑色区/迷雾内目标不能点击、框选、悬停读实时信息或通过 ID 下令；地面探索 MOVE 可用。
8. 自动索敌不能越过本方视野；已有目标失踪后只走最后位置；已释放箭矢按既定规则结算。
9. 未发现 enemy_tc 不出现在 derived；事件及资源余量不泄露；调试视角变化前后，相同模拟状态的 AI observation 完全相同。
10. 玩家→AI→全图→玩家的调试切换不改变任一阵营 explored 内容、命令阵营或已知静态记录。
11. G 只触发一次，输入框不抢键；进入取消建造，退出恢复合法输入；重开不会继承旧队伍快照。

### GPU / 人工画面验收

- 开局只有己方基地和单位附近亮起，其余纯黑；移动探索留下暗色已知地形。
- 同一屏幕上能同时区分黑色、暗色、明亮三态；敌军离开视野后连同血条、阴影、选择圈一起消失。
- 已知建筑暗色快照保留正确阵营装饰，真实建筑在幕后变化不穿帮。
- 屋顶、树冠和单位脚部不因屏幕空间误判被切碎；记忆对象遮挡顺序正常。
- 最大/最小缩放、拖动到四角、改变窗口尺寸后迷雾仍对齐，无地图边缘漏出草地。
- G 面板可查看两方不同的探索轨迹；全图显示完整战场；退出后黑色未探索区域正确恢复。
- HUD 不变暗；调试圈、路径和全图信息在正常模式下不残留。

### 性能验收

记录 100、300、500 个视野源时的 10 Hz 更新耗时、纹理上传次数、记忆代理数与帧耗时；100 源场景先以每次更新 2 ms 为优化目标，实际结果由当前机器测量，不能在未测试前保证。

普通帧不创建新的迷雾纹理，不逐单位分配全屏遮罩。视角切换只选择已有阵营数据并刷新显示，不重新扫描原始 SLP，也不复制每阵营整套美术资源。正确性优先；达到性能瓶颈后再测量并引入增量算法。

## 13. 实现记录（2026-09-22）

已实现逻辑、记忆、渲染、G 调试、交互/战斗/AI 过滤及六个 2D 场景接入。具体操作、文件位置、测试结果与当前边界见 [战争迷雾使用与实现说明](../../fog-of-war.md)。

实现中将记忆存储、展示调度与调试控制整合进 `FogOfWarHolder`，纯画面快照生成放在 `fog_memory.gd`；共享访问规则放在 `fog_access.gd`。因此实际文件拆分与第 11 节建议名称不同，职责和信息边界保持一致。暂不增加可选 `known_static` AI 协议字段，避免将记忆代理混入实时实体列表。
