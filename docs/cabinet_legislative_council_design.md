# 内阁 AI 重构设计：立法会直接重写五部门 Python 源码

设计草案 · 2026-11-22 · 基线 `new_ai@bb60b193` · 范围为 `ai_service_python` 的 `cabinet` 运行时

## 1. 一次更新实际改变了什么

**立法会可以直接重写 `economy.py` 中的任意函数，包括替换 `EconomyDept.act()` 的整个函数体。** 首相提交行为要求，LLM 阅读正在使用的 Python 源码并返回补丁。立法会把补丁应用到当前版本的一份独立源码副本，得到真实的新版 `.py` 文件。一个新的 Python 工作进程从这个版本导入完整内阁，接续本队对局。之后原有调用 `self.economy.act(f)` 自然进入改写后的函数。

建议首版沿用**本局本队发布**。例如红队能在第 101 轮切到 `r5`，蓝队和其他对局各自使用自己的版本。工作进程加载的文件形如 `releases/<r5内容摘要>/ai_service_python/brain/cabinet/departments/economy.py`。研发仓库是内建版本的来源；若要让这项改动成为今后所有对局的默认值，可以把同一份差异作为普通 Git 变更评审、合并和发布。当前任务只涉及设计。

### 为什么选用新进程加载源码

`CabinetRuntime.__init__` 创建五个部门实例，同时把它们保存在具名属性和 `self.departments` 元组里。还有跨文件的函数引用，例如 `general.py` 使用 `from .economy import idle_producer`。Python 重新加载模块时，既有实例继续使用原类，其他模块此前导入的名字也不会自动重新绑定。因此仅覆盖文件并调用 `importlib.reload(economy)` 会产生新旧代码并存的局面。新进程从同一发布目录正常导入所有模块，一次解决实例和依赖绑定。见 [内阁运行时](../ai_service_python/brain/cabinet/runtime.py)、[前线将军](../ai_service_python/brain/cabinet/departments/general.py)及 [Python 3.12 模块重载语义](https://docs.python.org/3.12/library/importlib.html#module-importlib)。

## 2. 用一份真实的函数补丁说明

假设首相提出「木材低于 200 开始优先采集，补到 320 恢复常规分工」。现有 `boost_resource` 会在经济部每轮更新时设置固定增量，无法表达两个阈值之间要记住上轮状态。下面是针对分支基线的示例补丁。它读取已有的观测、复用 `BOOST_RUSH`，并为经济部实例增加布尔状态 `wood_priority`。函数内部可以自行定义分支、循环和辅助函数。

```diff
--- a/ai_service_python/brain/cabinet/departments/economy.py
+++ b/ai_service_python/brain/cabinet/departments/economy.py
@@ -62,5 +62,13 @@
     def act(self, f) -> None:
-        """Gathering costs nothing: staff the resources the open requests are short of, and the one an order asked for."""
-        for resource, amount in self.boosts.items():
+        wood = f.obs.economy.wood
+        if wood < 200:
+            self.wood_priority = True
+        elif wood >= 320:
+            self.wood_priority = False
+
+        boosts = self.boosts.copy()
+        if getattr(self, "wood_priority", False):
+            boosts["wood"] = max(boosts.get("wood", 0.0), BOOST_RUSH)
+        for resource, amount in boosts.items():
             self.field.demands[resource] += amount
         self.field._economy(f)
```

在新工作进程里，正常执行 `CabinetRuntime._govern → self.economy.act(f)` 就会读到木材库存。先观察到 199、再观察到 250 时，两轮均提高木材权重；达到 320 时本法案的加权结束，原有资源需求继续生效。这个例子按**目标存续期**安装函数，玩家清空该指令后，由发布管理器撤销法案。

文档示例已做函数级验证：补丁与基线文件匹配，在内存副本上连续输入 `200、199、250、320、250、199`，采木加权依次为关、开、开、关、关、开，六轮均保留原有食物需求。真实村民转岗、工作进程交接及重复 tick 去重属于第 7 节的后续集成验收。

## 3. 首相提交什么，立法会可以改哪里

首相先判断能否用现有任务书、拨款优先级或前置任务达成目标。资源不足、正在等待回执或没有可见塔址，都应报告相应阻塞；已有行动却缺少决策算法时，首相才立案。入口有两处：解读玩家新指令时直接识别，或根据部门报告和多个有效观测识别执行中的缺口。后一路也适用于国策和首相主动目标。首相冻结验收例、行为边界和目标有效期，生成代码的模型只负责提出源码改动。

| 对象 | 必要内容 |
| --- | --- |
| 首相的立法需求 | 案号、`match_id/team/session_epoch`、来源指令或国策、目标修订号、基础发布摘要、目标部门、缺口证据、正反例、撤销条件 |
| 立法会发给 LLM 的上下文 | 基础版目标文件的原文、相关调用者及跨模块引用、部门基类和状态契约、必要的本队观测样例。用提交作业时记录的版本选文件 |
| LLM 的返回 | 结构化的 `proposal_id`、`base_release`、`unified_diff`、新增或变更的状态字段及默认值、变更说明。验证器自行从差异计算实际文件、符号和依赖 |
| 发布清单 | 五个模块的完整文件摘要、可信运行时与依赖版本、父版本、法案集合及依赖关系、状态格式版本、测试报告。发布目录由服务计算并以内容摘要标识 |

可写范围为下列五个模块。一案可改任意一个或多个模块中的方法、模块级函数及私有辅助函数，可新增函数、重写构造函数或重组算法。对外调用契约由真实调用者决定，例如 `IntelDept.update` 的返回值供后续部门读取。私有函数可以改签名并一并修改调用者；跨部门公共函数变更须覆盖所有受影响的调用点。需要改变五部门以外的服务协议或游戏机制时，首相收到具体的缺失能力，可另走常规工程变更。

| 可写模块 | 需要一起检查的调用或状态 |
| --- | --- |
| `economy.py` | `update/draft/train/act`、村民需求单和城镇中心窗口；`idle_producer` 也供前线将军使用 |
| `intel.py` | 侦察动作和 `IntelBrief`，尤其是其余部门和首相使用的威胁字段 |
| `general.py` | 集结姿态、生产建筑到兵种的选择，以及逐建筑调用的 `train` |
| `defense.py` | 墙与箭塔的需求、候选位置、在途施工回执 |
| `tech.py` | 时代储蓄、研发候选、城镇中心预留窗口及国库专款 |

在首相现有的 `premier_orders` 解读和 `OrderLedger.accept` 之间增加立案分支，允许「等待立法」子目标与普通任务并存。已送立法的目标不重复进入 `pending()`。等待期间可独立执行的任务照常处理。首相排序入口即使没有拨款请求也能读取待判缺口。发布成功只表示部门已装上新算法，指令的完成仍以游戏观测为准。见 [首相](../ai_service_python/brain/cabinet/premier.py)和[指令台账](../ai_service_python/brain/cabinet/ledger.py)。

## 4. 改到哪个目录，谁来执行

| 组件 | 职责与数据边界 |
| --- | --- |
| AI 服务主进程 | 对 Godot 提供原有 `POST /v3/ai/tick`。持有会话路由、活动发布号、请求缓存、发布台账和模型凭据。统一发起 LLM 请求、验证工作进程输出，只有主进程可以提交一轮的结果 |
| 立法会后台作业 | 按基础摘要从只读发布库取源码，在私有暂存目录应用补丁，生成完整发布目录，运行验证，通知主进程版本已就绪 |
| 每队的内阁工作进程 | 从指定发布目录导入唯一的一套 `brain` 包，运行整个 `CabinetRuntime`。五部门、`field`、国库和施工队可继续共享 Python 对象，部门现有函数签名和调用顺序可沿用 |
| 版本与状态存储 | 不可变的源码版本供复盘、重启工作进程和回滚。每队检查点、事件、模型决定和 tick 提交记录按会话隔离。容器部署需为这些数据配置持久目录 |

**源码落盘。** 立法会从活动发布复制或只读分层挂载整棵服务代码树到 `staging/<job-id>/`，仅为目标五部门文件建立独立可写副本。核对补丁路径、文件类型、基础摘要和原文上下文后，按文本补丁修改文件。拒绝越界路径、链接、二进制、构建脚本和测试改动。对最终目录重新计算实际差异。多模块改动齐备、验证通过后，同一文件系统内原子发布为只读 `releases/<摘要>/`。目录出现只表示可加载。

**Python 加载。** 启动新的隔离工作进程，以该发布的 `ai_service_python/` 作为唯一项目包根，使用固定 Python 与依赖，并保留数据目录的相对布局。工作进程正常导入 `brain.cabinet.runtime` 并构造 `CabinetRuntime`；`from .departments.economy import EconomyDept` 此时指向补丁后的源码。启动检查核对实际加载的模块路径、源文件摘要和发布清单，避免误用系统路径中的旧包或陈旧字节码。首次实施需发布包含工作进程管理器的 AI 服务；后续法案只启动新的本队工作进程。

**执行隔离。** 模块导入、测试、状态恢复和正式对局都可能执行生成的 Python，统一放在受操作系统约束的工作环境。建议部署为独立低权限账号或容器，代码与基础数据只读、临时空间有界、禁外网、无模型凭据、无宿主控制套接字，限制内存、CPU、进程数并由外部计时器处理死循环。工作进程只拿本队可见观测和已校验的模型决定，通过有大小和类型约束的 IPC 返回数据。AST 和单测用于提早发现错误，运行隔离和外部结果校验独立存在。容器方案的部署依据见 [Docker Engine 安全说明](https://docs.docker.com/engine/security/)。

**现有调用链要一起迁移。** `MultiAgentService` 目前直接调用 `session.runtime.tick`，后台线程还会调用 `planning_brief`、`planning_context` 和 `apply_plan`。建议新增会话运行时代理，将这些调用与日志提取、对局总结和战略记忆加载转给本队工作进程。方案生成另用专门的工具响应及 token 预算，适配普通工具调用和本地 Ollama，复用现有调用配额。模型网络访问、工具选择及请求目的地由主进程掌握。见 [后台调度器](../ai_service_python/brain/multi_agent/scheduler.py)和[模型适配器](../ai_service_python/brain/llm_proxy.py)。

## 5. 从第 100 轮旧代码切到第 101 轮新代码

假设红队已提交第 100 轮，活动版本为 `r4`，新版为 `r5`。候选版本在后台准备，正常 tick 无需等待 LLM、构建或测试。

| 时点 | 主进程和两个工作进程的动作 |
| --- | --- |
| 后台准备 | 旧进程照常应答。新进程从 `r5` 启动，导入模块并演练状态恢复。未能在切换时限内准备好的候选继续等待，旧版先接下一轮 |
| 选择切换边界 | 主进程先检查重复序号和观测指纹。对新序号核对会话、基础版本、目标有效期、当轮玩家指令及已提交事件序号。把 tick 和后台模型结果放进同一会话事件序列。窗口变更应在选版本之前处理，不能依赖现有调度器在 `runtime.tick` 之后才更新的 `instruction_revision` |
| 交接状态 | 在已提交事件的边界取得最终检查点，含第 100 轮以及其后已接受的模型决定。候选导入这份状态并报告相同的来源版本和事件序号。预加载期间落后的候选先追上最终检查点；中途生成的影子命令一律不外发 |
| 试跑第 101 轮 | 新进程调用原有 tick 入口，实际执行新版 `EconomyDept.act()`，返回命令、状态和待提交事件。主进程核对会话、序号、命令合同和状态连续性。此时旧进程仍停在第 100 轮的提交边界 |
| 一次提交 | 验证通过后，以（会话、观测序号）为唯一键，一次记录输入指纹、`r5`、新状态检查点及完整响应，再切换本队活动进程并向 Godot 返回。日志和私有播报按提交键投递。若连接在发送后断开，同一请求重试返回同一批带原 ID 的命令 |
| 首轮失败 | 新进程报错、超时或输出不合法时，丢弃它对第 101 轮的全部输出。旧进程从第 100 轮状态处理同一输入；只提交旧进程的结果。一次法案涉及两个部门时，两份新代码同成同败 |

主进程把工作进程的命令当作待审核输出，只接受本队允许的命令种类、实体所有权、可见目标、目录成本、数量和预算等约束。对需要专款或单位租约的命令，还需从可信输入与上一轮已提交记录复核拨款和租约，不能仅采信新代码进程自报的核验结果。Godot 沿用现有命令验证器。相同序号但指纹不同仍报告冲突。宿主重启时以最后一条提交记录恢复版本、检查点及响应；未提交的试跑可丢弃。见 [游戏命令校验器](../scripts/ai_gateway/command_validator.gd)。

## 6. 旧状态如何交给新函数，怎样退回

**检查点是本次重构的主要工程量。** 需要新增显式、带版本的状态导出与导入协议。保留能影响下一轮决策的状态，使用带类型的普通数据、稳定 ID 和引用表。新进程先构造自己的类与依赖，再恢复对象关系。禁止从生成代码进程反序列化任意 Python 对象。以下是首批必须覆盖的内容：

| 状态 | 恢复与验证方式 |
| --- | --- |
| 五部门、国库、施工队、`field` | 从同一对象图重建引用；逐项核对 `book` 的需求键、请求 ID 和 `_serial`、科技储蓄、专款、正在生产的单位及施工回执。换代码后新需求单不得与旧编号碰撞 |
| 行动与任务 | 保留在途命令 ID、任务、单位租约、已消费回执、上轮序号。观察到同一个已下达的训练或施工命令时不重复派发 |
| 首相与调度 | 保留开放指令、任务进度、已接受的规划、播报去重和逻辑时钟。后台响应带会话、目标修订、请求 ID 与来源发布号，过期结果丢弃或重提。回放使用已记录的输入、模型结果和影响决策的时间值 |
| 新版私有字段 | 法案申报字段类型、默认值和迁移规则。采木例新增 `economy.wood_priority: bool = false`，旧状态缺字段时取默认值。改变旧字段语义时须演练正向恢复及退回旧版所需的投影 |

**首轮之后才发现问题时**，按最近一次**已提交**的状态恢复兼容版本，并继续处理下一个新序号。例如 `r5` 已运行到第 135 轮才报错，就从第 135 轮的状态切回，保留这段时间内已经花掉的资源、领到的命令回执和玩家新指令。不能把第 100 轮冻结的旧进程直接接回。缺少可验证的向后状态投影时，该候选只具备新局启用资格。若活动进程与后备均无法恢复，则返回可重试的服务错误，保留最后提交记录及未消费的观测序号。

**取消与后续法案。** 把法案与来源目标绑定。清空或明确取代指令时，主进程先停用受影响版本再处理该轮。窗口出现尚未解读的冲突时先暂停相关法案，解读后按仍有效的法案集合选版；为受指令约束的法案预备可立即接管的后备版本。同一函数先后被两个法案重写时，记录适用基础和依赖，撤销前案时连同依赖案一起停用，保留可独立应用并验证通过的法案。禁止直接逆向覆盖当前文件。待审补丁的基础版本已变化时重新生成或重新应用，并重跑验证。不同局、不同队及新的会话代号分别路由。

## 7. 验证与交付顺序

| 阶段 | 可以判定完成的结果 |
| --- | --- |
| 1. 把内建内阁移入工作进程 | 同一批观测和模型结果分别经过现有进程内入口和新代理，逐轮对比命令 ID、需求单、拨款、状态、回执与播报；记录 tick P95/P99 和状态传输大小 |
| 2. 建立检查点与恢复 | 在有施工回执、专款和开放指令的中途，以相同源码更换进程。连续运行与恢复运行产生相同的后续结果，重复 tick 命中原缓存 |
| 3. 用固定补丁验证完整发布 | 用第 2 节补丁演练真实差异应用、语法编译、隔离导入和行为回放。库存序列 `199 → 250 → 320 → 250 → 199` 预期为开、开、关、关、开。覆盖初始恰为 200、其他资源加权保留，另验证有可用村民及木源时实际采集分工改变 |
| 4. 连通首相与真实 LLM | 现有任务与代码缺口正确分流。模拟基础版本冲突、补丁截断、无效语法、运行超时，确认原对局继续。改写 `idle_producer` 时覆盖经济部与前线将军两个调用方。五个模块各有一个可观察的函数改写用例 |
| 5. 验收实时切换 | 一案同时改两个部门，在其中一个失败时验证零项生效。覆盖双队隔离、提交前后断连、重复序号、指令同轮清空、后续回滚和服务恢复。记录法案 ID、父子版本、源码差异、状态格式、`effective_seq` 和回滚原因 |

可复用 [内阁运行时测试](../ai_service_python/tests/test_cabinet_runtime.py)、[国库测试](../ai_service_python/tests/test_cabinet_treasury.py)和[调度器测试](../ai_service_python/tests/test_multi_agent_scheduler.py)。首个端到端里程碑是：**只改 `economy.py` 的函数体，让同一局的下一轮实际进入新函数；同一输入最多提交一个结果，并能带着最新对局状态退回旧代码。**
