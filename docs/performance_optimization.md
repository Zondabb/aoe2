# 大地图性能排查与优化

## 卡顿的原因

默认地图扩大到 480 × 480 后，场景有 1081 个实体，其中包括 980 棵树和其他 90 个资源对象。原先适用于少量对象的处理方式仍遍历全部场景：

- 迷雾在每个物理帧处理所有资源的可见性，并重复取消不可见对象的选择状态；发现森林后，记忆代理也加入同一个实体容器，进一步扩大遍历范围。
- 小地图每帧为每个已发现资源单独生成多边形绘制指令。发现全部森林的测试中，有约 950 个记忆标记，单是这些标记就增加约 950 次绘制调用。
- 每个移动单位先枚举所有静态障碍，再让避让器重新扫描这份列表。同一帧的多个单位重复处理远处所有树木。
- 导航在已有半径缓存之间切换时，仍同步完整的 480 × 480 网格；没有阻挡变化的重建也会清空、重新填写所有格子。
- 遮挡轮廓每帧枚举全图静态对象及其图像，重复排序、配置材质和重绘遮罩。

地图规模和资源数量放大了这些成本，尤其在探索了大量森林、同时移动多个单位时。人物显示缩小本身不是上述遍历和绘制量增加的原因。

## 实现方式

### 迷雾与记忆

真实实体、视野源、动态单位分别缓存，记忆代理不再参与真实实体扫描。树木等静态对象只在迷雾刷新时处理；动态单位继续逐帧检查，避免敌人走出视野后残留。仅在显示状态发生变化时切换可见性或取消选择。

可见静态图像的记忆快照及代理复用；图像变化后更新，隐藏对象继续使用最后看见的外观。迷雾逻辑保持原来的 0.1 秒更新间隔，原版视野距离不变。

### 小地图批量绘制

原有标记位置、占地、视角过滤及绘制层次保留。每次标记更新时，将资源、建筑、单位的小四边形合并到一个彩色三角形网格；每帧只提交一次网格绘制，再画摄像机框、边界和命令提示。

标记的三种显示层采用线性分组，避免为近千标记重复调用比较排序。小地图读取迷雾维护的真实实体列表，并复用同一迷雾版本、同一占地位置计算的静态可见性；位置、占地或迷雾版本变化，以及动态单位、新增对象，均回退到当前视野查询。队伍颜色变化会立即刷新网格颜色。

这使用 Godot 的 [CanvasItem.draw_mesh](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html#class-canvasitem-method-draw-mesh) 接口。网格保存在小地图对象上，并在标记变化或窗口尺寸改变时重建。GPU 对比测试检查标记覆盖完全相同，颜色差异不超过网格颜色存储的一个 8 位步长。

### 静态碰撞与导航

导航服务维护 8 × 8 模拟单位的静态空间桶；大型占地写入所有覆盖的桶。单位避让只查询本帧预测移动范围附近的障碍，再进行原有精确碰撞检查。查询范围包含单位半径以及所有可选方向的预测距离，不会漏掉转向后的碰撞。

建筑插入、移除、占地变化、放置预览转为地基和资源耗尽会使索引更新。没有导航服务的小型测试场景保留原有全列表路径。

寻路仍使用 1 个模拟单位一格的精度。半径缓存切换仅同步两个占地层之间不同的格子；阻挡未变化时保留路径及半径缓存。没有通过减少树木或降低碰撞精度换取性能。

### 遮挡轮廓

静态图像维护空间索引，按摄像机视口查询。图像、变换或场景成员变化使缓存失效；单位动画仍逐帧处理。遮挡副本和材质参数复用，无变化时停止重绘遮罩，并保留渲染后端完成更新所需的帧。

## 测量与复现

测试使用 Godot 4.7.1、Intel UHD Graphics 770、OpenGL Compatibility、1280 × 720 窗口，并关闭垂直同步。默认地图、资源数量及素材保持不变。完整基准包含开局、探索 14 片森林后回到基地，以及额外 48 个单位行军三个场景。

行军场景每个渲染采样固定推进一次 `1/60` 秒的单位模拟，使优化前后的单位执行相同工作量；每阶段预热 30 帧，采样 240 帧。平均值和 P95 用于比较，不能当作所有硬件和实际对局的帧率保证。引擎的 CPU Performance 监控约每秒刷新，可能包含前一阶段，因此完整基准以直接测得的帧间隔及绘制次数为主要结果。

```powershell
godot --path . --rendering-method gl_compatibility --script res://tests/benchmark_default_map.gd -- --label current
godot --headless --path . --script res://tests/benchmark_fog_dense.gd
godot --headless --path . --script res://tests/benchmark_static_navigation.gd
godot --path . --rendering-method gl_compatibility --script res://tests/benchmark_unit_occlusion.gd
```

完整基准输出 `.godot/default-map-performance-current.json`；专项基准分别输出迷雾、导航 JSON 或遮挡日志。测量时应顺序运行，避免其他基准争用 CPU / GPU。

### 本机最终对比

优化前源代码保存在忽略目录内的独立项目中，使用同一份基准脚本；最终先运行优化前项目，再运行优化后项目。以下为本机最后一轮数据，原始结果见 [performance_results.json](performance_results.json)。

| 场景 | 原平均帧耗时 | 新平均帧耗时 | 原 P95 | 新 P95 |
| --- | ---: | ---: | ---: | ---: |
| 默认开局 | 3.681 ms | 1.140 ms | 17.425 ms | 3.792 ms |
| 已探索 14 片森林、950 条记忆 | 78.382 ms | 1.851 ms | 89.639 ms | 9.781 ms |
| 上述地图加 48 个行军单位 | 172.420 ms | 14.672 ms | 180.334 ms | 28.255 ms |

行军场景全帧绘制调用从 1027 次降至 76 次，平均帧耗时约减少 91.5%。大批单位的场景仍有周期性峰值，表中 P95 明确保留；不是恒定 60 FPS 的承诺。开局、探索及行军场景分别有 1081、2031、2079 个实体容器子节点，优化前后一致，资源始终为 1070 个。

专项微基准也定位并验证了对应热点：

| 操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 迷雾开局空闲物理帧 | 4.87 ms | 0.015 ms |
| 迷雾大量探索后完整重建 | 19.41 ms | 6.83 ms |
| 两次已缓存的导航半径切换 | 21.00 ms | 2.53 ms |
| 首次跨地图长距离寻路 | 31.62 ms | 6.63 ms |
| 基地空地、单单位静态避让 | 0.702 ms（扫描全表） | 0.0034 ms（局部查询与避让） |
| 全资源可见、基地视角遮挡更新 | 3.423 ms | 0.363 ms |

专项微基准分别运行，数字用于解释热点，不能直接相加作为某一帧总耗时。
