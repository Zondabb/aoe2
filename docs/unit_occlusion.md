# 单位被遮挡时的轮廓

人物等单位被建筑、树木或资源贴图遮住时，只在被遮住的身体边缘显示队伍颜色轮廓。未被遮住的部分保持原样；地面阴影、透明门洞和建筑放置预览不触发轮廓。轮廓随当前动画帧、朝向、镜像和队伍颜色更新。

迷雾隐藏的单位不会产生轮廓。已探索区域的建筑记忆参与遮挡，但只注册到表现层分组 `occlusion_memories`，不参与模拟。前景单位会清除自身覆盖范围的建筑遮挡标记，避免后方单位的轮廓画到前景单位身上。

## 实现

- `scripts/presentation/unit_occlusion.gd`：每个游戏视口共用一张遮挡图，只收集屏幕内可见的单位与静态 Sprite2D；按 Z、Y 和节点顺序绘制。使用两个颜色通道保存绘制序号，支持超过 256 个绘制对象。销毁对象后会释放对应副本。
- `shaders/occlusion_depth.gdshader`：仅保留不透明实体像素，排除贴图阴影与透明区域。
- `shaders/occluded_unit_outline.gdshader`：比较单位与遮挡物的绘制序号，结合当前动画帧的透明边缘生成轮廓。轮廓位于建筑实体之上，界面仍沿用原有层级。

遮挡图按实际渲染分辨率更新，并跟随相机和窗口缩放。复制动画帧和更新材质在低优先级 `_process` 中一起完成，必须早于画布重绘；不要挪到 `frame_pre_draw`，否则 WebGL 上可能出现材质参数与贴图帧错位。运行时不读取 GPU 图像，也不需要修改原始美术资源。无图形服务器不安装该渲染器。

## 验证

```sh
godot --path . --rendering-method gl_compatibility --script res://tests/render_unit_occlusion.gd
godot --headless --path . --script res://tests/run_fog_of_war.gd
```

渲染测试需要图形后端，覆盖局部遮挡、前后排序、阴影和门洞、镜像、连续切换动画、队伍颜色、相机缩放、窗口缩放、迷雾、超过 256 个绘制对象以及对象清理。实际对战场景截图输出到 `.godot/unit-occlusion-match.png`。受限环境可通过 `--log-file` 将日志写到项目 `.godot/` 中的绝对路径。

在编辑器运行项目，进入单人对战，即可看到初始城镇中心屋顶下村民的轮廓；指挥村民进出建筑，检查轮廓随遮挡消失或出现。联网对战使用同一套客户端表现逻辑。

Web 版按 [Web 发布说明](../deploy/web/README.md) 重新导出，在浏览器进入对局后检查同样效果，并缩放浏览器窗口。本次本地验证包位于忽略目录 `dist/web-outline/`；部署时应重新导出最终版本。
