# 中国、条顿陆地兵种与四时代系统

本次扩展从本机《帝国时代 II HD》的 `empires2_x1_p1.dat`、SLP 和语言文件导入中国、条顿的陆地单位、建筑及相关升级。正式对局从黑暗时代开始，可以依次升级到封建、城堡和帝王时代。

当前目录包含 **41 种单位、25 种建筑、26 项科技**。单位数量包含同一兵种的各个升级形态；旧地图使用的 `swordsman` 兼容 ID 不计入这 41 种。数据来源是本地 HD 数据 `VER 5.7`，不是《决定版》的最新平衡数据。

## 1. 开始游戏与操作

1. 主菜单进入单机设置，选择中国或条顿、地图和对手，然后开始游戏。
2. 顶栏显示当前时代和食物、木材、黄金、石料。默认地图加入了石矿，可以让村民右键采集；采矿场可以接收黄金和石料。
3. 选中村民，点击 **经济建筑（B）** 或 **军事建筑（V）** 打开建筑页。灰色按钮的提示说明所需时代、前置建筑、科技或资源。
4. 每页最多显示 12 个内容按钮，按 **PageDown / PageUp** 翻页，**Esc** 返回单位指令。建造页保留房屋 E、磨坊 I、采矿场 G、伐木场 Z、兵营 B、靶场 A、马厩 L；新增建筑的快捷键显示在按钮上。生产和研究页使用 `Q W E R T A S D F G Z X`。
5. 选中生产建筑，点击对应兵种训练，或点击“研究……”完成兵种升级。训练村民仍使用 **C**。

经济建筑页包括房屋、磨坊、采矿场、伐木场、农田、市场、铁匠铺、城镇中心、修道院、大学和世界奇观。军事建筑页包括兵营、靶场、马厩、攻城武器厂、城堡和墙塔。中国现在也可以建造马厩，具体可生产的骑兵由文明科技树决定。

农田需要磨坊，建成后可以右键安排村民采集食物。当前每块农田提供 175 食物；玩家的农田耗尽后需重新安排建设。规则 AI 在附近天然食物不足时维持 2–4 块有效农田：本地 AI 可花费 60 木材重播自己的空农田，Python / 命令捕获 AI 使用普通建造命令补建。

## 2. 升级时代

选择己方**已建成且空闲的城镇中心**，点击“升级时代”，或按 **U**。城镇中心的训练队列必须为空，也不能同时研究其他科技。选中城镇中心时，信息区显示升级名称和百分比。

| 目标时代 | 费用 | 研究时间 | 已建成的前置建筑 |
| --- | --- | --- | --- |
| 封建时代 | 500 食物 | 130 秒 | 兵营、磨坊、伐木场、采矿场中任意两种 |
| 城堡时代 | 800 食物、200 黄金 | 160 秒 | 靶场、马厩、铁匠铺、市场中任意两种 |
| 帝王时代 | 1000 食物、800 黄金 | 190 秒 | 大学、修道院、攻城武器厂中任意两种，或一座城堡 |

“两种”按建筑类型计算：两座磨坊只算一种；地基、放置预览、敌方建筑和已经摧毁的建筑不计入。时间为游戏模拟时间。

每个阵营同时只能进行一次时代升级。费用在开始时一次性扣除；升级期间城镇中心不能训练单位。再次点击取消按钮或按 **U** 可取消并全额退款。承担研究的城镇中心被摧毁时，也会取消并退还本次费用。暂停或对局结束时，研究不继续计时。

时代是阵营状态，中国和条顿可以处于不同的时代。升级完成后，己方生产、建筑按钮和建筑外观自动刷新；建筑生命上限及护甲采用对应时代数据，并保留已有生命比例。帝王时代没有后续时代升级。

一个简便的发展路线是：黑暗时代修建磨坊和伐木场；封建时代修建铁匠铺和市场；城堡时代修建大学和修道院，或直接修建城堡。

## 3. 陆地兵种

下表中的箭头表示**需要在相应生产建筑研究升级**，不是一到时代就自动获得终级单位。部分基础单位只受时代限制，例如城堡时代的骑士和帝王时代的巨型投石机；火药兵种还需要大学中的化学。

| 生产建筑 | 中国与条顿共有的兵种线 | 文明差异 |
| --- | --- | --- |
| 城镇中心 | 村民 | — |
| 兵营 | 民兵 → 剑士 → 长剑士 → 双手剑士 → 冠军剑士；长矛兵 → 长枪兵 → 长戟兵 | — |
| 靶场 | 步弓手 → 弩手；掷矛手 → 精锐掷矛手；骑射手 | 中国可继续升劲弩手、重装骑射手；条顿可训练火枪手 |
| 马厩 | 斥候骑兵；骑士 → 重装骑士 | 中国可升轻骑兵，并有骆驼兵 → 重装骆驼兵；条顿可将重装骑士升级为游侠 |
| 攻城武器厂 | 轻型冲车 → 中型冲车；轻型投石车 → 中型投石车；弩炮 → 重型弩炮 | 中国可升重型冲车；条顿可升重型投石车，并可训练手推炮 |
| 城堡 | 爆破兵、巨型投石机 | 中国：诸葛弩 → 精锐诸葛弩；条顿：条顿武士 → 精锐条顿武士 |
| 修道院 | 僧侣 | 当前支持空闲时治疗附近受伤友军 |
| 市场 | 贸易车 | 当前可生产与移动，尚无往返贸易收益 |

主要解锁时点：黑暗时代可以训练村民、民兵；封建时代开放长矛兵、步弓手、掷矛手、斥候骑兵和贸易车；城堡时代开放骑士、骑射手、攻城武器、僧侣和特色兵种；帝王时代开放巨型投石机、符合文明限制的火药单位以及终级兵种升级。

研究按文明、时代、前置科技、建筑状态和资源检查。完成升级后，同阵营已有的对应单位和正在训练的对应单位都会换成新形态，不会再次扣费。现有部队保留生命比例和当前命令；生产列表用升级形态替换旧形态。

## 4. 建筑与科技

| 开始可建的时代 | 建筑 |
| --- | --- |
| 黑暗时代 | 房屋、兵营、磨坊、伐木场、采矿场、农田、木栅栏、哨站 |
| 封建时代 | 靶场、马厩、铁匠铺、市场、石墙、城门、瞭望箭塔 |
| 城堡时代 | 新城镇中心、修道院、攻城武器厂、大学、城堡；研究后可用垛墙、警戒箭塔 |
| 帝王时代 | 世界奇观；研究后可用大型箭塔、炮塔 |

开局已有的城镇中心在黑暗时代可正常使用；**新建**城镇中心需要城堡时代，费用为 275 木材、100 石料。

建筑前置关系包括：农田和市场需要磨坊，靶场与马厩需要兵营，攻城武器厂需要铁匠铺。建筑完成后才算满足前置条件。

大学中可以研究垛墙、警戒箭塔、大型箭塔、化学和炮塔。大型箭塔以前一档警戒箭塔科技为前置，炮塔以化学为前置。兵种升级在所属的兵营、靶场、马厩、攻城武器厂或城堡中进行。按钮提示显示实际费用和时间。

科技研究占用当前建筑，同一建筑不能同时训练或进行其他研究，同一阵营不能重复研究同一项科技。取消研究或研究建筑被摧毁会全额退还本次研究费用。

## 5. 地图编辑器与旧地图

地图编辑器的建筑和单位目录与游戏共用同一份数据，因此可以放置新增兵种、建筑和石矿。保存的 JSON 仍通过对象 ID 表示种类，不需要把贴图或 DAT 嵌入地图。

主菜单的单机地图选择流程保持不变，选取保存的地图文件即可开始。旧的 `swordsman` 对象 ID 保留兼容支持。地图是初始场景描述，**不是对局存档**：时代、研究队列、已完成科技等运行中状态不会保存到地图文件。正式对局仍从黑暗时代开始；编辑器中预先放置的高级单位、建筑属于作者布置，不会因为初始时代而被删除。

具体尺寸、对象编辑及保存操作参见[地图编辑器使用说明](map_editor.md)。

## 6. 实现结构

| 文件 | 职责 |
| --- | --- |
| `data/civilization_catalog.json` | 原版来源信息、文明可用性、单位/建筑基础数值、升级关系、时代图像引用 |
| `scripts/data/game_catalog.gd` | 将 JSON 转成共享的 `UnitDef`、`BuildingDef`，统一名称、素材和建造条件查询 |
| `scripts/core/match_state.gd` | 阵营资源、时代、已完成科技及生产条件 |
| `scripts/systems/age_progression.gd` | 每阵营一项的时代研究、前置检查、计时、取消和退款 |
| `scripts/systems/technology_progression.gd` | 按建筑管理研究任务，应用单位线和防御建筑升级 |
| `scripts/entities/building_agent.gd` | 训练、建造、时代外观和建筑属性更新 |
| `scripts/entities/farm_agent.gd` | 农田食物采集；普通建筑不会被误判为可采集资源 |
| `scripts/systems/land_support.gd` | 僧侣治疗与有攻击能力建筑的自动射击 |
| `scripts/ui/hud_controller.gd` | 时代显示、分页建造和生产按钮、研究进度与条件提示 |
| `scripts/systems/ai/ai_progression_manager.gd` | 为本地 AI 建造升时代前置建筑、保留升级资源并发出研究命令 |
| `tools/slp_export/import_civilizations.py` | 离线读取 DAT、语言及科技树，生成目录并调用图像导出 |
| `tools/slp_export/original_graphics.py` | 按 DAT 图像引用合成 SLP 主体、附属层及玩家颜色遮罩 |

游戏运行时读取生成好的 JSON 和 PNG，不依赖原版安装目录或 Python。建筑图像按“建筑 ID → 文明 → 时代”选择，单位按“单位 ID → 动作”选择。图像保留原版热点、方向、层偏移和玩家色遮罩，沿用已有 Godot 阵营染色器。

移动速度在 `GameCatalog.MOVEMENT_SPEED_SCALE` 统一按原版数据的 **4 倍**转换，以适配本项目地图尺度并恢复导入前的移动节奏。例如村民为 3.2 格/秒、民兵为 3.6 格/秒、步弓手为 3.84 格/秒、骑士为 5.4 格/秒。原始 JSON 数值保留不变，兵种之间的速度比例保持一致；该系数只影响移动，不改变攻击、采集、生产和研究计时。旧地图的 `swordsman` 别名继续使用原有速度。

单位和建筑的原版基础视野、累计时代视野加成使用独立的 `GameCatalog.VISION_DISTANCE_SCALE = 4.0` 换算为项目距离。例如村民半径 16、步弓手半径 24、城镇中心半径 32；侦察骑兵从黑暗时代的 16 增长至帝王时代的 40。原始 JSON 保留原版格数，转换后的定义供迷雾、目标发现和联机副本共同使用。详细规则与验证见[迷雾及视野说明](fog-of-war.md)。

研究任务使用建筑弱引用；计时和执行前检查建筑是否还存在，避免访问已经释放的对象。兵种升级修改现有实体定义，而不是删除后重新创建，从而保留选中状态及现有指令关联。

联机由主机推进模拟，客户端发送研究/取消命令；快照同步时代、已完成科技、研究进度及升级后的实体类型。客户端使用同步状态显示进度，不再独立推进第二套计时。

本地规则 AI 会修建时代前置建筑，预留升级费用，并在进攻阶段继续扩建基地。建造位置在开局空位用完后继续向地图中心搜索。Python AI 服务也接入了石料、时代状态和研究命令，并使用游戏观测中的可训练、可研究列表；其精简数据文件通过 `python ai_service_python/tools/export_land_catalog.py` 从游戏目录生成。

## 7. 当前实现边界

这次完成的是上述两文明的陆地目录、素材、基础数值、可用性、生产/建造接入，以及四时代和兵种线升级机制。与完整原版规则仍有以下差异：

- 不包含海军、码头、水域寻路、英雄或战役专属对象。
- 导入的是 DAT 基础属性；完整文明加成、独特科技、经济科技、铁匠铺属性科技、僧侣科技等没有全面实现。铁匠铺目前可建造并参与前置条件，不提供完整升级页。
- 化学目前用于解锁对应火药内容，没有完整实现原版的攻击加成。
- 单位沿用项目现有通用战斗框架。攻城范围伤害、兵种类别附加伤害、诸葛弩多发攻击、爆破兵自爆、冲车驻军、巨型投石机打包/展开等专用机制尚未完整实现；巨型投石机的移动与战斗图像分别来自原版的打包、展开形态。
- 僧侣支持基础自动治疗，不包含招降、圣物搬运和圣物收益。贸易车没有自动贸易路线与收益，市场没有资源买卖，世界奇观没有倒计时胜利条件。
- 城门当前使用可通行建筑的简化逻辑，没有原版的自动开合与阵营通行控制。建筑射击采用现有抛射物逻辑，没有驻军箭数等完整规则。
- 农田没有玩家自动重种、农业科技和完整农田容量加成；规则 AI 有食物补给策略。

地图中的高级内容可以用于检查素材、移动和通用战斗；以上未实现机制不应当作完整对战平衡来验证。

## 8. 重新导入与验证

依赖和导入命令见[SLP 工具说明](../tools/slp_export/README.md#chinese--teutons-land-catalog-and-four-ages)。导入会更新目录和生成素材，应先确认本地原版数据与 `openage` 源码路径。

针对时代与文明内容的 Godot 检查入口：

```powershell
godot --headless --path . --script tests/run_age_progression.gd
```

如需渲染检查，去掉 `--headless` 并加入脚本参数：

```powershell
godot --path . --script tests/run_age_progression.gd -- --render
```

该检查覆盖目录资源引用、文明限制、时代费用/前置/暂停/退款、兵种升级后状态保留、农田采集及 HUD 基本接入。其他联机、地图和原有玩法检查仍使用仓库中的对应测试入口；单个时代测试通过不代表已验证全部原版特殊机制。
